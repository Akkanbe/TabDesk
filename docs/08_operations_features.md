## 実装上の注意

- 保存状態の通知はタブ内容の更新通知から分離し、通常の保存失敗と原本保護による停止を区別する。
- 既存の自動保存の再試行（1 / 2 / 4秒）は維持する。警告は保存成功まで残す。
- ホットキーの nil は明示的な JSON null として保存する。キーを省略すると、旧設定との互換処理で既定値へ戻るため。
- タブ番号の空欄は詰めない。タブ2だけを有効にしたときもタブ2へ作用する。
- 設定の形式・重複は保存前に検証する。Carbon の登録失敗は保存後に表示し、成功した割り当ては使用できる。
- 設定画面がキーウィンドウの間はグローバルホットキーの操作を実行せず、画面を表示中はタブ切替によるアプリ前面化を抑止する。
- ログ処理は `RotatingLogFile` で共有し、追記と世代更新をロックする。世代名と同名のディレクトリ・シンボリックリンク等は削除せずエラーにする。
- ログファイルへの書き込み失敗でも標準出力と PoC の画面ログは維持する。

## 確認手順

1. `./scripts/test.sh`：Core とアプリ層の全テストを実行する。アプリ層は実ウィンドウ監視を停止し、一時ディレクトリで保存失敗・復旧・原本保護を検証する。
2. `swift build --product TabDesk` と `swift build --product TabDeskPoC` を実行する。
3. 起動した本体のメニューで「ホットキー設定を開く」を選ぶ。タブ1とタブ2の設定欄を順にクリックして同じキーの組み合わせを押し、保存時に重複エラーになることを確認する。
4. タブ2以外の「×」で割り当てを解除して保存し、画面を開き直して値が維持されること、設定したキーでタブ2が選ばれることを確認する。最後に「既定値を入力」→「保存して適用」で戻せる。
5. 保存失敗の再現は通常のユーザー設定を壊さず、テスト `PersistenceStatusTests` で確認する。画面側は実際の保存エラー時に警告アイコンから詳細・再試行へ進める。
6. `RotatingLogFileTests` は小さい容量上限で、上限到達・3世代保持・巨大な日本語メッセージ・同時追記・失敗後復旧を検証する。

画面の描画確認用：`TABDESK_TEST_PREVIEW_PATH=/tmp/tabdesk-hotkeys-preview.png ./scripts/test.sh --filter HotkeySettingsTests/settingsControlsFitInsideWindow`

実アプリとの Carbon ホットキー競合や AX 操作は自動テストの対象外。設定画面の適用結果で OS の登録失敗を確認できる。
