# TabDesk v2 設計メモ

作成日: 2026-08-28。v2 のスコープ決定と設計判断の記録。進行に合わせて追記する。

## スコープ(2026-08-28 決定)

機能優先・段階実装。v1 と同じく段階ごとに実装 → テスト → 実機確認 → コミット。

- 段階 A: v1 残件(タブ並べ替え UI、フルスクリーン/最小化ウィンドウの除外)
- 段階 B: `tabdesk://` URL スキームの既定 OFF 化(仕様 §5「配布前の必須対応」)
- 段階 C: タイルレイアウト(タブごとに 自由配置 / 縦の等幅カラム)
- 段階 D: マルチディスプレイ対応

**見送り**(今回のスコープ外): Developer ID 署名・公証(アカウント準備ができてから)、
Sparkle(依存ゼロを維持)、ScreenCaptureKit のタブサムネイル(画面収録権限+月次再承認の
トレードオフが大きい)、背景「枠」ウィンドウ。

## 横断: スキーマ進化の方針

`WorkspaceState.currentVersion` は **1 のまま**にし、新フィールドは「追加+デコード時デフォルト」で
後方互換にする。`StateStore.load()` はバージョン不一致を `.bak.json` 退避+初期化で扱うため、
バージョンを上げると既存ユーザーの state.json が事実上破棄される。2 フィールドの追加に移行機構は過剰。

- `Tab.layout`(段階 C): 手書き `init(from:)` で `(try? decodeIfPresent) ?? .free`。
  キーが無い v1 ファイルも、将来の未知の enum 値も `.free` に落ちる(ファイル全体を壊さない)
- `ManagedWindow.displayID: String?`(段階 D): 明示 CodingKeys に case を足すだけ
  (optional は合成デコーダが `decodeIfPresent` になるので v1 ファイルは nil = 主ディスプレイ)
- 既知の制約: 旧バイナリで新形式のファイルを開くと読めるが、次の保存で新フィールドが落ちる
  (ソロ開発では許容)

## 段階 A の判断

- タブ並べ替えは右クリックメニュー「上へ移動 / 下へ移動」。手組み NSStackView +全行再構築の
  UI にドラッグ&ドロップは過剰(ドロップ位置表示・再構築との競合対策が必要になる)。
  クリック時に tab.id から index を引き直す(render 時の index はメニュー表示中に古くなりうる)
- フルスクリーン判定は AX 属性 `"AXFullScreen"`(SDK に公開定数なし)。対象 macOS での実測結果を
  下記に記録する。属性が取れない場合は v1 と同じく対象に残す(fail-open)。実機確認の結果、
  「frame == 画面全体」ヒューリスティックは不要と確定した
- 最小化ウィンドウも登録候補から除外する。最小化中の窓は frame を書けても raise で復帰せず、
  登録しても「切り替えたのに出てこない」死にエントリになるため。**登録済み**の窓が後から
  最小化された場合は登録を維持する(reconcile は最小化を含む全列挙と突合しているので安全)。
  副作用: 未復元エントリは対象の窓が最小化されている間は自動紐付けされない

### AXFullScreen 実測記録(macOS 26.5)

- 2026-08-28: CLI(swift スクリプト)からの読み取りは**環境要因で判定不能**だった。
  `AXIsProcessTrusted()` は true なのに、全アプリで kAXSubroleAttribute すら
  attributeUnsupported(-25205)を返す(ターミナル配下の未署名子プロセスでは AX が縮退する模様)。
  署名済みアプリ内からの測定が必要
- 実装は**安全側に倒してある**: `fullscreenRaw`(生値、nil = 属性なし)を `?? false` で判定するため、
  属性が無い環境では「除外されない」= v1 と同じ挙動になるだけで害はない。
  除外した窓は必ず `enumerate: excluded:` としてログに出るので、誤検知(普通の窓が除外される)も
  実測(フルスクリーン窓が fs=true で除外される)もログで確認できる
- **2026-08-29 実機実測(macOS 26.5、`tabdesk://windows`)**: 属性は**正常に機能する**。
  - ネイティブフルスクリーン中の Safari の窓が `excluded: [... [fullscreen] ...]` として除外された
  - 通常の窓は全アプリで `fs=false`(nil ではない)。確認できたアプリ: Finder / LINE /
    Docker Desktop(Electron 系)/ Google Chrome / システム設定 / Claude / Slack / Ghostty
  - 結論: フォールバックヒューリスティック(frame == 画面全体)は不要。属性ベースの判定を正式採用

## 段階 B の判断

- 仕様 §5 の 2 案のうち「既定 OFF の明示設定」を採用。`#if DEBUG` 案は build_app.sh の既定が
  `CONFIG=debug` なので実質ゲートにならず、URL スキームは動作確認・自動化チャネルとして
  残す価値があるため
- `PersistedToggle(key: "URLCommandsEnabled", defaultValue: false)` で全コマンドを一括ガード
  (読み取り系の例外は作らない)。メニューバーに「URL コマンドを許可(自動化用)」を追加
- 残存リスク: 同一ユーザーの任意プロセスは `defaults write` で有効化できる。ただしローカルの
  敵対プロセスはそもそも自分で AX 権限を要求できるため、この経路だけ塞いでも防御にならない。
  ここでのゲートは「配布物が既定で操作口を開けない」ことが目的

## 段階 C の判断(2026-08-28 実装)

- v2 のタイルは **縦の等幅カラム(columns)1 種のみ**。`Tab.layout: free | columns`。
  列順 = サイドバーのウィンドウ一覧の並び順(bound の窓のみ。未復元は列数に入らない)
- 列の計算は `Tiler.columnFrames`(純関数)。境界 x を「累積値の丸め」で整数化し、
  各列の幅を先に丸めたときに出る右端の隙間/はみ出しを構造的に無くす
- **設計の要**: 定常状態では `ManagedWindow.frame` が常に「適用済みのタイル rect」を保持する。
  これによりスナップバック・reconcile のずれ検知・到達 frame 採用は v1 のまま無変更で動く。
  列の再計算は**構造イベント時のみ**(タブ切替 / レイアウト変更 / 登録 / bind / 解除 / 窓消滅 /
  画面構成変更)。reconcile が毎回理想列を書き直す設計にすると、最小サイズ制約のあるアプリ
  (Docker Desktop 等)で「理想値書込 → 失敗 → 到達値採用 → また理想値」の発振ループになる。
  発振しないことは回帰テスト(minSizeWindowDoesNotOscillate)で固定
- 窓消滅(destroyed / vanish)は同期経路で IPC を挟めないため、`pendingRetileTabIDs` に予約して
  次の reconcile が 1 回だけ消化する(予約を先に空にするので失敗しても繰り返さない)
- 列に収まらない窓(最小幅制約)は到達 frame を採用し、隣の列と**重なったまま**になる(許容制約)
- 編集モードは free のタブでのみ記録する。columns ではドラッグは常にスナップバック
- `.free` に戻したときは現在の列 rect がそのまま自由配置の固定 frame になる(旧配置は保存しない)
- UI: タブの右クリックに「レイアウト: 自由配置 / 縦に等分割」、ウィンドウ行の右クリックに
  「上へ移動 / 下へ移動」(= 列順の入れ替え)。ヘッダに「— 縦に等分割」を表示

## 段階 D の判断(2026-08-28 実装)

- `ScreenLayout` は `displays: [DisplayLayout]`(id / frame / contentArea / parkPoint、先頭 = 主)に拡張。
  `parkPoint` / `contentArea` は「主ディスプレイの値」を返す互換アクセサとして残し、既存コードと
  テスト約 100 本を無修正のまま通した(D1)。本番実装は `SystemScreenLayout`(NSScreen.screens から構築)
- ディスプレイ識別子は `CGDisplayCreateUUIDFromDisplayID` の UUID 文字列
  (`CGDirectDisplayID` は再起動で変わりうるため)。`ManagedWindow.displayID: String?` として永続化、
  nil = 主ディスプレイ(v1 データもここに落ちる)
- **退避先はディスプレイごとに計算**する。配置全体の右端に達する画面は自画面の右下隅を使い、
  それ以外は右端にある実ディスプレイの右下隅へ fallback する。退避先の 1px 線は AeroSpace と同じ許容
- **レビュー修正(2026-08-29)**: 「右下隅 −1px」は配置全体の**外縁**でしか成立しない。
  横並びだけでなく、下側の画面がより横長な縦積みでも窓本体が露出する。また maxX と maxY を
  別画面から合成すると L 字配置の空白を指す。そのため global maxX を持つ**実画面**を fallback 先にし、
  maxX がそこへ届かない画面だけ画面跨ぎのコスト(実測 50〜270ms/窓)を許容する
- 「隅にいる」判定(x 比較)は**その窓のディスプレイの隅 x** と行う。判定の正は従来どおり
  `parkedWindowIDs` フラグで、隅 x は補助(誤検知しても「退避済みを再退避」で無害)
- 登録時の「主ディスプレイへ引き込み」を廃止。窓はいたディスプレイに留まり
  (`display(containing:)` = 中心点 → 最大交差 → 主、で所属決定)、所属を記録する。
  編集モードで別ディスプレイに置いたら所属もそちらへ更新
- サイドバーは主ディスプレイ固定。sidebarWidth を引くのは主ディスプレイの contentArea のみ
- columns はディスプレイごとにグループ化してそれぞれの領域で等分(画面をまたぐ 1 本の列にはしない)
- **ディスプレイ消失時**はシンプルに主ディスプレイへ clamp(既存の reapplyLayout 経路。frame は
  書き換わる)。「切断中は frame を温存し、再接続で元に戻す」磨き込みは D3 として保留 —
  実運用(4 画面環境)で挙動を見てから要否を判断する
- 画面構成変更から reapply 完了までは moved/resized の編集記録を抑止する。OS による移動を
  editMode のユーザー操作と誤認し、永続 displayID を主画面へ変えないため
- inactive タブも reapply で論理 frame を更新し、解除・削除・終了時にも現在の画面構成で再 clamp する。
  切断済み画面の旧座標へ窓を戻さないため
- 診断: `tabdesk://dump` が各画面の DisplayID・各窓の所属を出す

## v2 レビュー後の実機確認

- [ ] URL コマンド OFF で `tabdesk://status` が無視され、ON にした場合だけ処理される
- [ ] フルスクリーン中・最小化中の窓が候補に出ず、解除後の未復元窓が自動で再紐付けされる
- [ ] 横並び、等幅/不等幅の縦積み、L 字配置で、非アクティブ窓が 1px を超えて露出しない
- [ ] 外部画面上の inactive 窓を切断後に解除しても主画面内へ戻り、画面外へ消えない
- [ ] editMode ON で外部画面を切断・再接続しても、窓の displayID が意図せず主画面へ変わらない

## 段階 D3(保留)

ディスプレイ切断中の frame 温存(fallback clamp を記録しない)。エンジンで最も繊細な変更になるため、
D2 の「主へ寄せる」挙動が実運用で不便だと分かってから着手する。
