## 方針

未登録の通常ウィンドウが登録済みウィンドウに隠れたとき、公開Accessibility APIで前面へ戻す。
他アプリのウィンドウレベルは変更せず、未登録窓を自動登録・移動・リサイズしない。
最小化、別Space、フルスクリーン、対象を一意に特定できない窓は操作しない。
設定は既定OFF。OFF中は追加のウィンドウ列挙と前面化を行わない。


## 設定と動作

メニューバーの「未登録のウィンドウを最前面に保つ」で切り替える（英語: Keep Unregistered Windows on Top）。
`UnregisteredWindowsOnTop` をUserDefaultsに保存し、再起動後も引き継ぐ。既定はOFF。

ユーザーの指定に従い、このモードでは入力フォーカスの維持より未登録窓の前面化を優先する。
登録窓に重なって隠れた未登録窓と、その手前で重なる未登録窓を奥から順に上げ、必要に応じてアプリをアクティブにする。
別画面など重なっていない窓は対象にしない。登録窓をクリックして前に出しても、ONの間は未登録窓を再び前へ戻す。
この挙動が不要なときはOFFにする。自動登録やレイアウト変更は行わない。

- タブ／画面切替完了後、および通常の約2秒間隔の監視で判定する。応答の遅いアプリや連続した移動中は補正が遅れる場合がある。
- 重なり順・位置に変化がなければAX列挙を省略し、10秒経過後は再評価する。
- 最小化・非表示アプリ・別Space・位置変更できない窓（フルスクリーン等）・ダイアログ／パネルは対象外。
- 退避点に1pxだけ残った窓は、画面上の重なり判定から除外する。
- AX参照で登録の有無を判定し、CG情報は一意に照合できる場合だけ可視性と順序の補助に使用する。
- 列挙中に窓の構成が変化した場合は次回に再試行。設定OFF、登録開始、タブ切替、終了、セッション非アクティブ化で古い処理を無効化する。
- 設定画面・改名・ドラッグ等の操作中は新たな前面化を開始しない。既に送信したAX呼び出し自体は取り消せない。

これはOSのウィンドウレベルを固定する実装ではない。システムUIや他アプリの特殊な浮動パネルより上になることは保証しない。
公開APIの範囲は[AppleのAXRaiseの説明](https://developer.apple.com/documentation/applicationservices/kaxraiseaction)に従う。
非公開API、追加依存、画面収録権限の追加要求はない。

## 確認手順

1. 新ビルドを起動し、メニューバーの「未登録のウィンドウを最前面に保つ」をONにする。
2. 未登録の通常窓を、タブに登録済みの窓と重なる位置に置く。
3. 登録済み窓をクリックして手前に出し、未登録窓が再び手前へ戻ることを確認する。
4. タブを切り替えても、未登録窓が登録窓の裏に残り続けないことを確認する。
5. 設定をOFFにし、登録済み窓を手前に出した状態が保たれることを確認する。

### 確認した原因と修正

1. レイアウト再適用のTaskが完了後も保持され、前面化側が永久に「レイアウト変更中」と判定していた。幅変更・折りたたみ・画面構成変更の両経路で、完了時に世代を検証してTask参照を解放する。古いTaskが新しい処理の参照を消さないことも検証した。修正前の回帰テストは幅変更・画面変更・処理の差し替えで失敗し、修正後は成功。
2. 未復元登録の探索Task全体を前面化の停止条件にしていた。探索中の待機だけでは停止せず、実際の登録／紐付け処理の予約と登録変更で競合を防ぐ。
3. 実稼働中のChromeでAXタイトルとCGタイトルの不一致を確認。位置・サイズ・PIDは一致していても厳格なタイトル照合で覆う窓が消え、背面のClaudeが検出されなかった。表示順序用の照合だけタイトルの一致を要求せず、双方向の一意性と位置・サイズ・PIDの一致を必須とした。撮影やURL操作の既存照合は変更しない。

修正前の実画面ではZedが登録済みTextEditの背面に残っていた。レイアウト修正後はサイドバーの折りたたみ／展開の後も、TextEditを前に出すとZedが戻った。
Claudeは検出できていたが、ChromeのCG番号が取得できず判定対象から落ちていた。タイトル照合の修正後は、Chromeと、その背後のClaudeを正しく検出することを読み取り専用の検証で確認した。

前面化を実行する際に件数だけをログへ出し、今後は「対象なし」と「処理が動いていない」を切り分けられるようにした。
追加後の自動テストはCore 288件・App 42件、合計330件成功。
証跡は `build/unregistered-fix/` に保持。

### レビュー後の追加修正

- 中断済みの列挙Taskが終了する前に設定の再ON・切替完了通知が届くと、その要求が失われていた。中断中に受けた要求だけを1回にまとめて引き継ぐ。通常の重複要求は重ねず、OFF・終了など再度の無効化で保留要求も破棄する。
- 画面上の全ウィンドウ一覧が列挙前後で完全一致することを要求していたため、別の窓の出現・消滅・移動でも候補全体を破棄していた。PID・番号・位置・サイズが不変の窓を最新の前後順で採用する。変化した窓と重なる範囲も操作せず、次の監視へ回す。一部を見送ったスナップショットはキャッシュしない。
- キャッシュの10秒期限を `Date` から `ContinuousClock` に変更し、時計の補正で期限が延びたり戻ったりする問題を避ける。

最初の2点は回帰テストで修正前の失敗を確認した。保留要求の破棄、関係のない窓の変化、重なる窓の変化、PID変更、一部だけ取得できた場合の再評価を含む6テストを追加。
既存の登録・表示順・フォーカス・終了処理を含め、Core 288件・App 48件、合計336件が成功。Releaseビルド・署名検証・差分チェック成功。ビルド／テストに警告なし。
