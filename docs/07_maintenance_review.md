## 変更と根拠

- `TabEngine.clamped(_:)`：呼び出しがない private な単一画面用関数を削除。実際の呼び出しは所属画面または配置領域を指定する overload を使用している。
- `TabEngine.focusTargetPID(in:)`：`Tab.representativeWindow` と同じ「最後にフォーカスした紐付け済み窓、なければ先頭の紐付け済み窓」の選択を共用。実行後の状態から選ぶタイミングは維持する。
- `WorkspaceMigration`：非 nil の `tab.displayID` は先行分岐で処理して `continue` するため、後段の nil 再判定を削除。
- コメント：単一画面時代の説明と、冪等性を計算量削減と混同した説明を修正。

## 維持する設計上の制約

- AX の同期 IPC は `BlockingExecutor` で実行する。MainActor 上でも await 中には状態が変わるため、復帰後の紐付け・画面接続・世代の再確認は削除しない。
- フルスクリーン観測の nil は判定不能。false に置き換えず、直前の判定を維持する。
- 画面切断中は記録位置を維持し、ウィンドウ移動を発行しない。
- 同一 pid の操作順、pid 間の並列実行、終了期限の処理は維持する。
- JSON の旧形式互換とバックアップ失敗時の書き込み抑止は維持する。
- `WindowDriver` と設定ラッパーはテスト分離・既定値登録の役割がある。小さな型という理由だけでは削除しない。

## 確認手順

1. `./scripts/test.sh`：切替、同時操作、終了時復元、移行、マルチディスプレイ、フルスクリーン等の既存テストを実行。
2. `swift build --product TabDesk` と `swift build --product TabDeskPoC`：両実行ターゲットをビルド。
3. `git diff --check`：差分の空白エラーを確認。専用 lint 設定はリポジトリ内で見つからなかった。
4. 実機では、同じタブに2窓を登録し、片方へフォーカスした後に別タブへ切替・元へ戻す。最後にフォーカスしたアプリが前面化することを確認する。
5. その窓の登録を解除して同じ切替を行い、残った窓のアプリが選ばれることを確認する。

自動テストは偽のドライバで検証する。実アプリの AX 応答、フォーカス、画面切断・再接続の手動確認は別途必要であり、自動テスト成功だけで全環境の無退行を保証するものではない。
