# 非公開APIの置き換え計画（2026-09-13）

## 目的と現在地

TabDeskの外部ウィンドウ管理を、公開Accessibility API中心の実装へ移行する。
画面選択→タブ変更→入力、配置、保存、復旧を維持し、非公開APIの変更で基本操作が使えなくなる依存を減らす。
この計画に沿って `codex/public-api-window-tracking` で実装中。最新の実装・検証状況は
[24_public_reference_migration.md](24_public_reference_migration.md) を参照する。実装済みと実機の合格判定は区別する。

- [x] 配布準備までの現状を `551a0d3`（`Prepare local release packaging and user guide`）としてコミットし、`origin/main` へプッシュ
- [x] 現行の呼び出し箇所・影響範囲と公開API候補を調査
- [x] 段階的な実装、検証、移行判断の計画を作成
- [x] 計画の承認後、現行版から分けた `codex/` 接頭辞の作業ブランチで試作開始

2026-09-13: `codex/public-api-window-tracking` で参照管理・独立Probe・専用Fixtureを実装し、実機で一部条件を検証した。
結果と未確認項目は [公開API方式の試作・検証](22_public_api_probe_results.md) を参照。本体への配線・非公開API削除は未実施。

2026-09-14: ユーザー指示により `AXFullScreen` 属性を暫定維持する案は採用せず、公開APIの位置変更可否に基づく配置保護へ置き換えた。
本体の登録・配置・復旧経路へ反映済み。詳細と検証範囲は [非公開フルスクリーン属性の置き換え](23_public_layout_protection.md) を参照。
窓ID取得関数の置き換えは別途継続が必要。

基準版では296テスト、本体Debug／Release・PoCビルドが成功している。直近の配布検証は `20_release_preparation.md`、4画面の操作検証は `18_maintenance_review.md` を参照する。
保存形式・依存ライブラリ・UIの全面変更は行わない。App Store対応や新機能追加は本計画の対象外。

## 置き換える依存と範囲

| 依存 | 現在の役割 | 方針 |
| --- | --- | --- |
| `_AXUIElementGetWindow` | AX参照からCGWindowIDを取得 | 基本操作の識別をアプリ内部の実行時IDとAX参照へ移す |
| `"AXFullScreen"` | 公開SDKに定数のない属性によるフルスクリーン判定 | 公開情報で安全に判定できる範囲を別途試作。窓番号の移行だけで解決済みにしない |
| CGWindowID中心の管理 | 通知、消滅判定、復旧、サムネイル、診断 | 操作用IDと補助的なOSの窓番号を明確に分離する |

窓の移動・サイズ変更・前面化は既にAccessibility APIで行っており、その操作を全面的に書き直す必要はない。
調査した公式資料とローカルSDKでは、AX参照からCGWindowIDへの一対一変換を保証する公開APIは確認できていない。

| 主な対象ファイル | 移行内容 |
| --- | --- |
| `Sources/TabDeskCore/AXWindow.swift` | AX参照と窓番号取得の分離、フルスクリーン判定 |
| `Sources/TabDeskCore/WindowEnumerator.swift` | 番号なしでの候補列挙、画面上・存在一覧の扱い |
| `Sources/TabDeskCore/Model.swift` / `WindowMatcher.swift` | 実行時の識別型、再同定候補。保存用UUIDとJSONは維持 |
| `Sources/TabDeskCore/WindowDriver.swift` / `TabEngine.swift` | 操作対象、参照更新、消滅と不明の区別、終了時の復旧 |
| `Sources/TabDesk/WindowManager.swift` / `Sources/TabDeskCore/AppWindowObserver.swift` | 通知からの参照照合、ポーリング、フォーカス、非同期操作の再検証 |
| `Sources/TabDesk/ThumbnailStore.swift` / `AppDelegate.swift` | サムネイル、診断出力、URLコマンドと番号の対応 |
| `Sources/TabDeskPoC/` / `Sources/AXShim/` / `Package.swift` | PoCも移行し、不要になったシムと依存ターゲットを削除 |

実装開始時に呼び出し元とテスト内の型依存を再検索し、この一覧以外の箇所も移行漏れを確認する。

## 採用候補の設計

「保存された登録」「現在操作できる窓」「OSの窓番号」を分ける。

| 情報 | 用途・寿命 |
| --- | --- |
| 既存の `ManagedWindow.id`（UUID） | タブ内の登録を識別。再起動後も保存情報として残る |
| 新しい実行時ID（型名は実装時に決定） | 現在のAX参照を識別。プロセスの世代と参照に対応付け、保存しない |
| `CGWindowID?` | サムネイル・診断等に必要なときだけ公開の窓一覧と照合。照合不能でも登録は保持 |

実行時IDを偽のCGWindowIDとして流用しない。既存JSONでは `windowID` と `pid` は保存していないため、保存形式を変えずに移行できる見込み。ただし実データの往復テストで確認する。

同一プロセスのAX参照は `CFEqual` で比較する。ポインタ値やハッシュ値だけを窓の永続IDにしない。PID再利用、相手アプリの再起動、AX参照の失効を区別する。
通知が未対応・欠落するアプリには、既存の定期確認を活用する。一時的なAX通信失敗、ロック中、空の列挙結果を、そのまま「窓が閉じた」に変換しない。

通常の操作は保持した参照に対して行い、OSの窓番号照合をホットキー処理の必須条件にしない。
参照が失効した場合は、同じ参照として確認できる候補を優先する。タイトル・サイズ等による再同定は同一性の証明ではないため、曖昧なら手動割り当てへ進める。
既存の `WindowMatcher` は起動後の再同定用に活用するが、終了時の復旧に緩い照合を流用しない。

CGWindowIDが必要な場合は、同一プロセスの候補を位置・サイズ・利用可能なタイトルで照合する。タイトル取得の権限制約や、読み取り間の窓移動も考慮する。
一意に見える一致でも誤対応がない保証にはならない。時間経過や配置変更で対応を再検証し、曖昧・不明な結果から窓を操作・削除しない。

## 第1段階: 操作しない追跡試作と成立性の確認

- [x] 新方式だけで窓の列挙、フォーカス参照、移動・サイズ・破棄通知から同じ窓を追跡する試作を作る。
- [x] 試作では窓を動かさず、専用書類を使って人が行った操作と追跡結果を照合する。利用中の設定ファイルは使わない。（独立Fixture自身が操作する専用窓で代替し、Probeは読み取りのみ。）
- [ ] 同一アプリの同名・同サイズ・重なった窓、タイトル変更、最小化、画面外退避、フルスクリーン、別Space、画面切断を調べる。
- [ ] 相手アプリ再起動、ロック解除、通知未対応、AX参照が再生成された場合の追跡継続・失敗を記録する。
- [ ] 比較用に旧方式の窓番号を記録する場合も、新方式の判断材料には渡さない。旧方式も失敗し得るため、正解扱いせず実窓と照合する。
- [ ] 列挙・通知処理の所要時間と、追加の権限なしで取得できる情報を計測する。
- [ ] `AXFullScreen` を読まずに通常窓／フルスクリーン／不明を区別できるか、対応アプリ・OSごとに検証する。

合格条件: 同名・同サイズの窓を取り違えず追跡でき、不明時の安全な保留と復旧方法があること。
単純な画面サイズ一致やフルスクリーンボタンの有無だけで状態を断定しない。成立しなければ本体移行を始めず、機能・対応環境・公開時期の選択肢を提示する。

## 第2段階: 識別型を分離して基本操作を移行

- [x] 実行時IDとAX参照の小さな管理箇所を追加する。新しいフレームワークや大規模な抽象化は導入しない。
- [x] Coreの操作引数・辞書・キューを実行時IDへ移行し、移行中は既存の取得方式を比較可能な形で保持する。
- [x] 候補一覧・窓登録・通知・フォーカス追跡を公開API方式へ順次切り替える。
- [ ] 非同期処理では、アプリの世代・参照・所属タブ・画面接続・終了状態を実行直前にも確認する。
- [ ] タブ番号受付時に対象タブUUIDを保持する挙動、画面選択直後のタブ変更、連打時の順序を維持する。
- [x] 保存データの読み込み・保存・旧版への読み戻しを、コピーしたfixtureで確認する。

各変更後の確認: `./scripts/test.sh` と本体・PoCのビルド。窓登録→画面切替→タブ切替→入力を専用書類で確認し、次の変更へ進む。
移行中の比較は開発用に限定し、新旧両方式から同じ実窓を重複操作しない。

## 第3段階: 消滅判定・復旧・補助機能を移行

- [x] `reconcile` がCGWindowIDの集合を基本操作の生存判定に使わないよう変更する。
- [x] 「存在確認」「消滅確認」「確認不能」を分け、タイムアウトや列挙失敗では登録・保存座標を失わないようにする。
- [ ] 参照失効後の再取得、手動割り当て、終了前の復旧を移行する。終了全体の3秒期限とアプリごとの並列処理を維持する。
- [x] サムネイルは一意な対応が確認できた場合だけ取得する。対応不明なら別の窓を撮影せず、その窓のサムネイルを省略する。
- [x] 同一画面内・別画面のフォーカス推定に使うCG情報と、基本操作の実行時IDを混同しない。
- [x] 診断ログでは登録UUID・実行時ID・OSの窓番号を区別する。
- [x] URLコマンドの `wid` は現行ではCGWindowIDを意味するため、別の意味に黙って変えない。公開APIで解決できる範囲の互換性と、解決不能時の明示エラーを設計する。
- [ ] サムネイル省略やURL互換性など、利用者に見える制約が増える場合は測定結果を示して承認を得る。デグレなしとみなして進めない。

各変更後の確認: 窓を閉じる場合とアプリごと終了する場合の登録保持の違い、窓が退避したままの通常終了、再起動後の復旧を確認する。
終了時に別の窓へ誤って再紐付けすることと、退避座標を正常な保存座標へ上書きすることを必ず回帰テストに含める。

## 第4段階: 非公開属性の扱いを確定し、依存を削除

- [x] 第1段階の結果に基づき、フルスクリーン判定と判定不能時の操作・復旧方針を実装する。
- [x] 判定不能を単純にfalseへ変換しない。すべての操作を止めることで退避窓が戻せなくなる場合も、解決済みとは扱わない。
- [ ] 信頼できる公開方式が成立しない場合、`_AXUIElementGetWindow` の除去と `AXFullScreen` の除去を別の達成状態として報告し、残存依存・制約を明示する。
- [ ] 本体とPoCが非公開関数なしで動くことを確認してから、AXShim呼び出し・シム・Package.swiftの依存を削除する。
- [x] ソース全体とReleaseバイナリを検査する。現在の関数は `dlsym` で取得するため、未解決シンボルの一覧だけでなく、関数名の文字列・実行時解決経路も確認する。
- [x] README、復旧ガイド、PoCの説明、既知の制限を最終実装に合わせる。過去の検証記録は履歴として残す。

## 回帰テストと実機の合格条件

| 対象 | 確認内容 |
| --- | --- |
| 識別 | 同名・同サイズ・同位置の複数窓、参照再取得、アプリ再起動、PID再利用を模した状態、遅れて届く旧通知 |
| 操作 | 次／前の画面、次／前・番号タブ、連打、空タブ、同じアプリの複数画面、マウスなしでの入力 |
| 競合 | 受付後の並べ替え・削除、画面切断、終了開始。古い要求が別の窓・タブに作用しない |
| 復旧 | 通常終了、専用環境での異常終了、ロック／スリープ解除、参照切れ、相手アプリ無応答、未復元の手動割り当て |
| 表示状態 | 最小化、通常の最大化、ネイティブフルスクリーン、別Space、ディスプレイ再接続 |
| 永続化 | タブ・登録UUID・ホットキー・保存座標の維持、設定バックアップ、旧版との互換性 |
| 補助機能 | サムネイルの対象誤りがないこと、画面収録権限なしでの基本操作、診断・URL互換性 |
| 応答性 | 現行版と同じ環境で比較し、メインスレッドがAX通信待ちにならないこと、操作順序と終了期限の維持 |

既存296テストに加え、取り違え・参照失効・通知欠落を再現する意味のあるテストを追加する。
実機では少なくとも現在の4画面構成と1画面、AppKit系・ブラウザ・Electron系のアプリで検証し、OSごとの未確認項目を記録する。
故障注入や復旧試験では専用書類・設定コピーを使い、実施前後の登録と配置を比較する。

最終確認コマンドは `./scripts/test.sh`、専用の `APP_OUTPUT_DIR` を指定した本体・PoCビルド、`./scripts/prepare_release.sh`、`git diff --check`。
Release成果物でも画面→タブ→入力と復旧を確認する。現行版との比較で再現性のある悪化があれば、修正または明示的な仕様判断が済むまで移行を完了扱いにしない。

## リリース判断と戻し方

第1段階を最初の判断点とする。追跡精度とフルスクリーン判定が成立するまで、本体置き換えの完了日や公開日を確定しない。
第2段階以降は小さなコミットに分け、機能の切り替えとリファクタリングを同じ変更に詰め込まない。

不合格なら作業ブランチを維持したまま、基準コミットから別の出力先に現行版をビルドして戻す。履歴の破壊や強制pushは使わない。
実機のアプリ入れ替え前には通常終了・窓の復元・設定バックアップを行う。戻す際も対応する設定コピーと旧版を使い、作業中の状態を失わないよう保管する。

「非公開API除去」はDeveloper ID署名・公証とは別工程であり、App Store対応を保証しない。
Appleは他アプリを操作するAccessibilityの用途をApp Sandboxと両立しない機能として挙げているため、初回のGitHub直接配布方針は維持する。
