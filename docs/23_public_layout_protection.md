# 非公開フルスクリーン属性の置き換え（2026-09-14）

ユーザーの指示により `AXFullScreen` を暫定維持せず、公開API方式への置き換えを進める。

- [x] 現在の登録・操作・保存・復旧経路を確認
- [x] 公開APIの位置変更可否に基づく保留状態を実装
- [x] 各書き込み直前と配置結果の採用前に可否を再確認
- [x] 判定不能時に編集座標を誤採用しない回帰テストを追加
- [x] 全テスト、本体Debug／Release、PoCビルドを確認
- [x] 専用窓で通常・全画面・通常復帰を実機確認
- [x] 結果と制約を記録

状態を「フルスクリーンか」と推測する方式から、「現在位置を変更できるか」に基づく操作保護へ変更する。
`AXUIElementIsAttributeSettable` に `kAXPositionAttribute` を渡して確認する。位置変更不可は保留、取得失敗は不明とし、実際の書き込みはどちらの場合も拒否する。
画面サイズやボタンの文字列で全画面かどうかを推測しない。移動不可の通常窓も保護対象となる。

この変更は全アプリのネイティブフルスクリーン状態を取得するAPIを実現するものではない。
外部アプリが変更可能と誤報告する場合や、問い合わせと書き込みの間の状態遷移は原子的に扱えないため、読み戻しと既存の失敗処理も維持する。

## 変更箇所

- `WindowLayoutAccess`: 公開の位置変更可否を「変更可／不可／取得失敗」に分ける。
- `AXWindow`: 非公開属性の読み取りを削除。位置・サイズ・前面化の直前に位置変更可否を確認し、不明でも書き込みを拒否する。配置完了直後も可否を確認して、不許可へ遷移した後の寸法を正常な到達値として返さない。
- `WindowDriver` / `TabEngine`: 保護状態を `isLayoutSuspended` / `layoutSuspendedWindowIDs` と命名し、ネイティブフルスクリーンの検知と混同しない。既存の保留・復帰・登録保持の仕組みを活用する。
- `WindowEnumerator` / `WindowManager`: 登録と再紐付けには変更可能の確認を要求。診断ログも「全画面」ではなく「配置保留」として記録。
- 編集モード: 保留をまだ検知していない窓でも、操作可否が不明なときは読み取った座標を保存しない。

## 実機検証

macOS 26.6.2、外部ディスプレイ上の専用Fixtureで実施。

1. 通常窓で、本体と同じAXWindowの `setPosition` により10px移動して元に戻ることを確認。
2. Fixture自身がネイティブフルスクリーンへ移行。NSWindowの状態がfullScreenであることを確認。
3. 本体の `setPosition`、`setSize`、`setFrame`、`raise` がすべて拒否され、実窓のframeが変わらないことを確認。
4. 通常窓へ戻した後、再び移動と元の位置への復帰が成功することを確認。
5. Fixtureを通常終了。TabDeskの設定は操作しない。

実行手順は [書き込み保護の確認](../Tools/PublicAXProbe/README.md#本体の書き込み保護を確認する)。
このチェックは専用のプロセス・窓だけを操作し、本体の稼働アプリや既存の登録窓は入れ替えていない。

窓ID取得の `_AXUIElementGetWindow` はまだ残っている。この記録はAXFullScreen属性の置き換えに関するもので、全非公開APIの除去完了を意味しない。
