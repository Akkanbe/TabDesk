# TabDesk 仕様書 v1/v2(ドラフト)

作成日: 2026-08-20 / 壁打ちセッションの決定事項を反映。未決事項は末尾に列挙。
2026-08-20 更新: v0 技術検証(docs/02_poc_results.md)の実測結果で §2.3 / §3.3 / §3.5 / §4 / §5 を改訂。

## 1. 概要

macOS 上で他アプリのウィンドウを「タブ」として管理するユーティリティ。

- 画面左端に常時表示のサイドバー(タブ一覧)を置く
- タブを切り替えると、そのタブに登録されたウィンドウ群だけが所定の固定位置に表示される
- タブ内の各ウィンドウは位置・サイズが固定され、動かされても元に戻る(スナップバック)

## 2. 技術方式(調査結果の要約)

### 2.1 前提となる制約

- **他プロセスのウィンドウを自アプリのウィンドウ内に埋め込む(reparent する)公開 API は
  macOS に存在しない**(Windows の `SetParent` 相当は不可能)。macOS 15 Sequoia /
  macOS 26 Tahoe でも追加されていない。SIP 無効化+私有 API(yabai 方式)でも埋め込みは不可。
- したがって本アプリは **「実ウィンドウ整列方式」** を採る:
  ウィンドウは独立したトップレベルウィンドウのまま、Accessibility API(AXUIElement)で
  座標・サイズを制御し「枠に収まっているように見せる」。
  AeroSpace が同方式(仮想ワークスペース)を SIP 無効化なしで商用品質実装済みであり、実現性は実証されている。

### 2.2 採用技術

| 目的 | 手段 |
|---|---|
| ウィンドウ移動・リサイズ | `AXUIElementSetAttributeValue`(kAXPosition / kAXSize) |
| ウィンドウ列挙 | `CGWindowListCopyWindowInfo` + アプリごとの AX ウィンドウ列挙 |
| AX 要素 ↔ CGWindowID 対応 | 私有関数 `_AXUIElementGetWindow`(業界標準の依存。私有 API はこの1点のみに限定) |
| イベント監視 | `AXObserver`(moved / resized / created / destroyed / focused)+ `NSWorkspace` 通知 |
| 非アクティブタブの退避 | 画面右下隅へ移動(完全画面外は OS が許さず **1px の縦線が残る**。AeroSpace と同じ) |
| 実装言語・UI | Swift 6 + AppKit(サイドバーは NSPanel)。SwiftPM でビルドし .app バンドル化 |

- **最小化・アプリ単位 hide は使わない**:最小化は Dock 汚染と復元アニメーションで低速。
  `NSRunningApplication.hide()` はアプリ単位のため「同一アプリのウィンドウを別タブに振り分ける」
  要件(決定済み)と非互換。
- 必要権限は **Accessibility(TCC)のみ**。v1 では ScreenCaptureKit(画面収録権限)は使わない。
- ウィンドウタイトルは AX 側(kAXTitle)から取得する(CG 側から取ると画面収録権限が要るため)。

### 2.3 受け入れる既知の制約(仕様として明記)

1. 退避ウィンドウは画面隅に 1px の線として残る(Dock 自動非表示でほぼ不可視にできる)
2. Mission Control には全タブのウィンドウが見える(OS 設定「アプリケーションごとにグループ化」を推奨)
3. Cmd-Tab / Dock クリックで非アクティブタブのウィンドウにフォーカスが移りうる
   → **フォーカス連動タブ切替**(§3.6)で吸収する
4. Electron / Java 系アプリは AX の応答が遅い・座標指定に従わないことがある
   → pid 単位の並列化と `AXUIElementSetMessagingTimeout` で全体への波及を防ぐ。
   最小サイズ制約(例: Docker Desktop は幅 940 未満にならない)は実在するため、固定 frame は
   「要求値」ではなく「適用後に読み戻した到達 frame」を基準として保持する
4'. AX を拒否するアプリがある(権限付与後も `apiDisabled` を返す。実測: Jump Desktop Connect、Claude)
   → 「管理不可」として登録候補から外し、理由を表示する
5. Accessibility 権限はサンドボックス非対応のため **Mac App Store 配布は不可**。
   配布は Developer ID 署名+公証(v2 スコープ)
6. macOS アップデートで AX 挙動が変わることがある(Tahoe で実例あり)。OS 更新ごとの回帰確認を運用前提とする

## 3. 機能仕様(v1)

### 3.1 決定事項サマリ

| 論点 | 決定 |
|---|---|
| 実現方式 | A. 実ウィンドウ整列方式(サムネイルなし) |
| 用途 | 配布も視野(設計段階から考慮、配布作業自体は v2) |
| 管理粒度 | ウィンドウ単位(同一アプリの複数ウィンドウを別タブに振り分け可) |
| 管理対象 | **明示登録制**(登録したウィンドウのみ管理。未登録ウィンドウは自由なまま) |
| ディスプレイ | v1 は単一(メイン)ディスプレイのみ → v2 で複数対応(窓は登録時のディスプレイに留まり、退避は原則同じ画面、内側の隅では配置外縁へ fallback。2026-08-28 実装。docs/04_v2_design.md) |
| 復元 | v1 からベストエフォート復元(bundle ID+タイトル等のヒューリスティック) |
| レイアウト | v1 は自由配置+位置固定のみ。v2 でタブごとに 自由配置 / 縦の等幅カラム を選択可(2026-08-28 実装。docs/04_v2_design.md) |

### 3.2 サイドバー

- 画面左端に常時表示の縦型パネル(`NSPanel`、floating レベル、全 Space 表示)
- 表示内容:タブ一覧(名前)、アクティブタブの強調、タブ追加/削除/リネーム、
  アクティブタブの登録ウィンドウ一覧、レイアウト編集モードのトグル
- 操作:タブはクリックで切替、ダブルクリック(または右クリック →「名前を変更」)で改名ダイアログ、右クリックで削除。
  パネル自体はキーウィンドウにならず(作業中アプリのキー入力を奪わない)、文字入力が要る改名だけ
  アプリをアクティブにしたダイアログで行い、終わったら元のアプリへ戻す
- サイドバー領域は管理対象ウィンドウの配置領域から除外する(重ならない)
- 背景の「枠」ウィンドウは v1 では描かない(明示登録制では未登録ウィンドウと混在するため、
  枠の錯視が成立しにくい。v2 で検討)

### 3.3 タブとウィンドウ登録

- タブ:名前付き。作成・削除・リネーム・並べ替え可能
- 登録方法(v1 は 2 経路):
  1. サイドバーの「+」→ 現在開いているウィンドウ一覧(アプリ名+タイトル)から選択
  2. グローバルホットキー「フォーカス中のウィンドウをアクティブタブに登録」
- 登録時、そのウィンドウの現在の frame を初期固定位置として記録
- 登録解除:サイドバーのウィンドウ一覧から解除。解除後は自由なウィンドウに戻る
- 登録候補は標準ウィンドウ(kAXStandardWindowSubrole)のみ。
  ダイアログ・シート・パネル・ネイティブフルスクリーン中・最小化中のウィンドウは登録対象外。
  `_AXUIElementGetWindow` が失敗する要素(Finder がウィンドウ一覧に混ぜる AXScrollArea 等)も対象外
- 登録したウィンドウは、そのときいたディスプレイに留まる(v1 の「主ディスプレイへ引き込み」は
  v2 で廃止。所属ディスプレイは保存され、切断中は主ディスプレイへ寄せる)
- 1 ウィンドウは同時に 1 タブにのみ所属

### 3.4 タブ切替

- トリガー:サイドバーのタブをクリック / グローバルホットキー(タブ 1..9 直接+前後移動)
- 動作:
  1. 旧タブの全ウィンドウを画面配置から計算した安全な右端へ移動(サイズは変更しない)
  2. 新タブの全ウィンドウを記録済み frame に復元し、前面化(raise)
  3. 新タブで最後にフォーカスされていたウィンドウにフォーカスを移す
- AX 呼び出しは pid 単位に並列化。1 アプリの無応答が切替全体をブロックしないこと
- 性能目標:登録 10 ウィンドウ規模で体感即時(目安 100ms 台)

### 3.5 位置固定(スナップバック)

実測(macOS 26.5)では kAXWindowMoved / Resized は**ドラッグ中にも約 100 ms 間隔で届く**。
そのため「即時復元」と「静止後に復元」のどちらも実装可能で、体感比較の結果 **デバウンス方式を採用**した。

- 通常モード(デバウンス方式):
  - 通知を受けたら復元を予約し、同じウィンドウの通知が来るたびに予約を延長する(既定 250 ms、設定可)
  - 通知が止んだら記録 frame を再適用する。ユーザーにはドラッグ中は自由に動き、離すと約 0.25 秒後に戻って見える
  - 再適用後も不一致なら、再び静止を待って最大 3 回まで再試行する。それでも戻らない場合は相手アプリの
    制約(最小サイズ等)とみなし、到達 frame を新しい基準として採用する
    (**掴まれている最中の一時状態を制約と誤認しない**ための手順。即時採用すると基準が劣化する — PoC で実証)
  - 退避中(非アクティブタブ)のウィンドウと、自分の操作で届いた通知(既に基準 frame にある)は無視する
- 即時復元方式は不採用(「少し動いてすぐ戻る」張り付き体感になり、リサイズ中にアプリ側と競合する)。
  設定項目としても提供しない(必要になれば後から追加)
- レイアウト編集モード(サイドバーのトグル or ホットキー):
  ON の間は移動・リサイズが(静止後に)新しい固定 frame として保存される。退避中ウィンドウの通知は編集モードでも記録しない。
  サイドバー領域に置かれた場合はコンテンツ領域へ寄せて記録し、窓もそこへ動かす
- 固定 frame は常にコンテンツ領域(サイドバーの右側)に寄せて保持する(登録・配置・編集のすべて)。
  ドラッグ中に一時的にサイドバーの下へ入るのは許容し、**マウスを離した瞬間**(グローバルのマウスアップ監視)に
  復元する。マウスアップを取りこぼした場合もデバウンス(250 ms)で戻る
- 「サイドバーと被らない」保証は **登録した窓に限る**(2026-08-22 決定)。未登録の窓は対象外
  (全窓を押し出す「立ち入り禁止帯」方式は見送り。必要になれば v2 で検討)

### 3.6 フォーカス連動タブ切替

- Cmd-Tab / Dock クリック等で「非アクティブタブに属するウィンドウ」にフォーカスが移った場合、
  そのウィンドウが属するタブへ自動的に切り替える(AeroSpace と同じ定石)
- フォーカス監視:`NSWorkspace.didActivateApplicationNotification` + AX の focused window 監視

### 3.7 ウィンドウのライフサイクルと整合性維持

- 登録ウィンドウが閉じられたらタブから自動除去。ただし**アプリごと終了した場合は除去せず「未復元」として保持**し、
  アプリが起動し直して同じ窓が現れたら自動で紐付け直す(2026-08-22 決定。除去すると永続化の意味が薄れるため)
- AX 通知は取りこぼしがある(Sequoia 以降 destroyed 通知の欠落報告あり)ため、
  **通知+低頻度ポーリング(2 秒間隔で CGWindowListCopyWindowInfo と突合)の二重化**で
  整合性を回復するリコンシリエーション層を最初から入れる
- スリープ/ロック解除・ディスプレイ構成変更時は全タブの状態を再適用する
  (AeroSpace で「ウィンドウが勝手に戻る」バグの温床だった箇所。状態はイミュータブルな
  スナップショットとして持ち、常に「あるべき状態」を再適用する設計にする)

### 3.8 永続化と復元

- 保存先:`~/Library/Application Support/TabDesk/state.json`(変更時+定期保存)
- 保存内容:タブ定義(名前・並び)、各登録ウィンドウの
  {bundle ID, アプリ名, タイトル, 固定 frame, 登録時サイズ}
- 実行中のウィンドウ同定は CGWindowID(セッション内でのみ有効)
- 再起動後の復元:bundle ID+タイトル(+サイズ)のスコアリングで同一ウィンドウを推定して再割当。
  **完全復元は原理的に不可能**(ウィンドウ ID は再起動をまたいで安定しないため)。
  マッチできなかった保存エントリはサイドバーに「未復元」として表示し、手動で再割当できるようにする
- 照合の厳しさ:起動直後は緩め(bundle ID 一致+タイトル部分一致やサイズ一致、またはそのアプリの窓が 1 つだけ)、
  稼働中の自動紐付けは厳しめ(タイトル完全一致相当)。曖昧なものは紐付けず未復元のまま残す
- 保存は状態変更のたびに 0.5 秒でまとめて書き、終了時にも書く。読めないファイルは `.bak.json` に退避して初期化

### 3.9 設定(v1 最小)

- ホットキー割当(タブ切替・登録・編集モード)
- フォーカス連動切替の ON/OFF
- 起動時に自動起動(ログイン項目)

## 4. 非機能要件

- 対応 OS:macOS 26 Tahoe(開発機 26.5)。将来的に 15 Sequoia も視野
- 常駐時 CPU 負荷:アイドルでほぼ 0%(ポーリングは軽量な列挙のみ)
- 権限:Accessibility のみ。初回起動時に `AXIsProcessTrustedWithOptions` で付与導線を出す
- 識別子:bundle ID は `io.github.akkanbe.tabdesk`(PoC は `io.github.akkanbe.tabdesk.poc`)。
  独自ドメインを持った場合は Resources/<Product>/Info.plist の CFBundleIdentifier / CFBundleURLName を変える
  (scripts/build_app.sh は plist から識別子を読む)
- 配布形態:v1 はローカルビルド(.app バンドル)。v2 で Developer ID 署名+公証
- 開発時の署名:ad-hoc 署名は再ビルドごとに TCC の権限が外れる(OFF→ON では直らず再登録が必要)ため、
  自己署名証明書「WTC Dev」(コード署名・常に信頼)で署名する。scripts/build_app.sh が自動検出する
- 依存ライブラリ:v1 はゼロ(ホットキーは Carbon `RegisterEventHotKey` を直接使用)

### v4: ディスプレイごとのタブ(2026-08-29 スコープ決定。v3 の後に実施)

現在の「1 つのアクティブタブが全ディスプレイの窓を支配する」モデルから、
**ディスプレイごとに独立したタブ集合**へのアーキテクチャ変更。

- [ ] タブは 1 ディスプレイに属し、そのディスプレイ上のウィンドウだけを管理する。
      タブ切替はそのディスプレイの窓だけを退避・復元し、他ディスプレイの表示は変わらない
- [ ] サイドバーは各ディスプレイの左端に 1 本ずつ置き、その画面のタブだけを表示する(2026-08-29 決定)
- [ ] ホットキーは「選択中のディスプレイ」のタブに作用する。選択中 = フォーカス中のウィンドウが
      ある画面、判定できなければマウスカーソルのある画面にフォールバック(2026-08-29 決定)
