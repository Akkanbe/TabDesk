最初はCGEventの通常文字入力と番号指定が届く一方、矢印キーが発火しなかった。
検証用送信プログラムを、HIDイベント状態・修飾キーの押下／解放・矢印キーの
numericPad/secondaryFn属性を付ける方式へ変更したところ、画面変更も成功した。
本体コードの変更は行っていない。切り分け中に誤った窓へ入った試験文字列は
合格判定に含めず、修正後の各専用入力欄の値とキーウィンドウを確認した。

キー送信はユーザーの明示許可のもと専用Fixtureに限定し、各操作前に前面PIDと
ロック状態を照合した。連続操作は約0.1〜0.2秒間隔の合成イベントであり、
物理キーボードの長押しリピート試験とは区別する。
物理的な画面抜き差し、1画面だけの構成、意図的なロック／解除は今回の再開試験では未実施。

## 手元での再確認手順

1. 各画面に2つ以上のタブと窓を用意し、窓内の入力欄にフォーカスする。
2. Control+Option+左右矢印で画面を変更し、Control+TabまたはControl+Shift+Tabでタブを変更する。
3. 文字を入力し、選択した画面・タブの窓へ届くことを確認する。
4. Control+Option+1／2でも同様に確認する。
5. TabDeskを通常終了して退避窓が戻ることを確認し、起動後に構成とキー操作が復元されることを確認する。

元の6タブ・8登録を復元し、新Releaseで起動した。7登録が再接続され、
試験前から未接続だった1登録も保持されている。タブ・登録ID、保存座標、
選択状態は通常終了後のバックアップと一致し、ホットキーはバイト単位で一致。
再接続時に更新される照合用情報（窓タイトル1件・登録サイズ2件）だけ差分があり、
それ以外の保存値は一致した。
