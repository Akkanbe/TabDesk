# 公開前のウィンドウ復旧確認

- [x] 復元失敗の条件と既存の回収経路を整理
- [x] 終了失敗後の再起動・タブ選択・登録解除を回帰テストで検証
- [x] 日英の復旧案内と手動の再検索をメニューに追加
- [x] 全テスト・ビルド・実機確認と利用者向け手順を整備

対象は、ロック中などに終了時の復元が失敗した場合の切り分けと窓の回収。保存済みの登録・配置を維持し、通常のタブ操作と既存の再紐付け処理を使用する。

## 条件と対処

| 条件 | 現在の動作・確認根拠 | 利用者の対処 |
|---|---|---|
| ロック中・ログインセッションが利用できない | 実機で AX の参照取得失敗と全窓の再紐付け失敗を観測。解除後は再紐付け・通常終了の復元に成功した。過去の全エラーがロック原因とは断定できない | 解除後に起動し、対象タブを選択。未復元なら再検索 |
| アクセシビリティ権限不足 | ウィンドウ操作を許可されない。手動再検索時は権限設定の案内を表示 | システム設定で TabDesk を許可し、再検索 |
| 相手アプリが無応答・参照が無効 | 参照再取得、既存参照による試行がともに失敗し得る。閉じたと確認できなければ登録を保持 | 相手アプリが応答する状態で TabDesk を再起動。未保存書類のある相手アプリを強制終了しない |
| 終了処理が 3 秒を超える | 終了期限を優先するため、途中の窓は戻らない可能性がある。既存の終了期限・並列処理テストで検証 | 再起動して対象タブを選択し、戻った窓を必要に応じて登録解除 |
| 強制終了・クラッシュ | 終了時の復元処理が走らない。最後に保存された登録からの再同定になる | TabDesk を再起動。設定ファイルを先に消さない |
| 位置変更が成功応答でも退避先に残る | 前回の実機調査で観測。位置だけの再適用と読み戻しを行い、画面外に残った結果は保存位置に採用しない | 対象タブを選んで確認。改善しなければ発生時刻とログを報告 |
| モニター切断 | 意図的にその画面の窓の操作を止め、保存位置を維持する。自動で主画面へ移さない | 元のモニターを再接続して対象タブを選択 |
| 最小化・ネイティブフルスクリーン | 再検索の対象外。既知のフルスクリーン窓は終了時も保護する | 相手アプリで解除してから再検索 |
| 同名の候補・タイトル変更 | 再検索は既存の厳格照合を使い、判別できない候補を残す。起動直後は既存の緩め照合を使うため完全同定は保証できない | 未復元の登録行をクリックし、正しい実窓を手動で選択 |

## アプリ内の操作

メニューバーに「ウィンドウの復旧手順…」と「未復元のウィンドウを再検索」を追加。再検索は保存済みの未復元登録だけを対象とし、タブの選択は変更しない。見つかった非選択タブの窓は退避されるため、結果表示でも対象タブの選択を案内する。再検索中の多重実行と終了開始後の実行を防ぐ。

ロック通知の受信時刻をログに追加し、既存のロック解除・復元失敗ログと突き合わせられるようにした。通知は診断用であり、ロック中の成功や消滅を判定する材料にはしない。起動前にロックした場合など、通知を観測できていない状態は推測しない。

## 回帰テスト

`WindowRecoveryTests` で以下を確認する。

- 自由配置・タイル配置 × AX 書き込み失敗・位置移動の無視の 4 ケースで、終了失敗後も保存された登録・論理配置が保持される。
- 保存・読込後に古いウィンドウ ID を使わず再紐付けできる。対象タブを選択すると表示領域へ戻り、登録解除後も実窓が表示位置に残る。
- 同名候補を自動で選ばず、手動で選んだ窓だけを復元する。

`WindowRecoveryGuideTests` で日英の結果付き案内が 800 × 800 pt 以内に収まり、ボタンが画面内に配置されることを検証する。実機での確認は別途行う。

## 実機での確認手順

1. 通常終了とバックアップ後に更新版へ入れ替える。
2. メニューから復旧手順を開き、案内とボタンを確認する。
3. 手動の再検索で結果件数が表示され、既存の登録・選択タブが変わらないことを確認する。
4. 確認専用の窓を非選択タブへ登録する。TabDesk を通常終了・再起動して対象タブを選び、窓の表示と登録解除後の位置を確認する。
5. 確認専用の窓・空タブを片付け、元のタブ・設定へ戻す。

ロックそのものや権限剥奪を自動操作で発生させる検証は行わない。過去の実機観測と失敗を模した回帰テストを分けて記録し、OS が操作を拒否する状態でも必ず回収できるとは案内しない。
