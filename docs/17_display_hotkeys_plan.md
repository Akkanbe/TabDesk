# ディスプレイ切替ホットキーの実装計画

状態: 実装・自動検証済み。2026-09-12に4画面で主要な操作導線の実機確認を完了。

## 目的と範囲

「ディスプレイを選ぶ → その画面のタブを切り替える → 入力を続ける」をホットキーだけで完結させる。次回の機能追加はこの操作に絞り、既存のホットキー設定・画面別タブ管理を拡張する。新しい依存や保存形式の大幅な変更は不要と見込む。

## 操作案

| 操作 | キー候補 |
| --- | --- |
| 次のディスプレイへ | Control + Option + → |
| 前のディスプレイへ | Control + Option + ← |
| 選んだ画面の次／前のタブへ | 既存の Control + Tab / Control + Shift + Tab |
| 選んだ画面のタブを番号指定 | 既存の Control + Option + 1〜9 |

新しいキーは既存の設定画面で変更・解除できるようにする。キー候補の他アプリとの競合は実機確認する。

接続中の画面を配置座標の左から右、同じ横位置なら上から下へ並べて循環する案とする。単一画面では何もしない。最初は次／前の2操作だけとし、画面番号の直接指定や上下左右4方向の移動は追加しない。

画面を切り替えた際は、その画面の選択中タブを維持し、そのタブで最後に使った操作可能な窓へフォーカスを移す。対象がなければ同じタブの操作可能な窓を登録順で選ぶ。マウスポインタは移動しない。

空タブ・未復元窓しかないタブでも操作対象の画面は選択でき、次のタブ操作を受け付ける。入力先を移せない場合は成功扱いの表示をせず、サイドバーに操作対象と窓がない旨を示す。最小化・フルスクリーン窓の扱いは既存の保護方針を維持する。

## 現在の実装と注意点

- `HotkeyAction` / `HotkeyConfig` に画面切替の操作はない。キー記録・競合検出・設定保存は再利用できる。
- `WindowManager.selectedDisplayID()` は前面窓・フォーカスキャッシュ・マウス位置から操作先を求める。明示的に選んだ画面を保持する仕組みが必要。
- タブ切替はすでに画面ごとに独立しており、`TabEngine.activateAdjacent` は直列区間で次のタブを決めている。
- 選択済みタブの再選択ではアプリの再アクティブ化を抑制している。画面切替では、配置を変えずに対象窓へフォーカスする経路が必要。
- 画面切替直後のタブ操作が古い前面窓を参照しないよう、画面選択とタブ操作の受付順を保証する。遅れて届くフォーカス通知による巻き戻りも防ぐ。
- 通常のクリックや Cmd+Tab で別画面の窓を選んだ場合は操作先も追従する。マウス移動だけでは明示選択を解除しない。未登録窓・同一アプリの画面間切替も検証する。

### 2026-09-09 実機テストの試行

- 更新版を起動し、ログで4画面のサイドバー生成、Accessibility許可、16件のホットキー登録を確認。
- UI操作ツールから画面切替・タブ番号指定・登録のキーを送ったが、TabDeskの操作発火を確認できなかった。登録キーは確認用の新規テキスト書類への制御文字入力となった。原因をアプリの不具合と断定できず、このツールによる実機ホットキーテストは未成立。
- 確認用書類の入力を取り消し、一時フォルダへ保存して閉じた。既存書類の内容とタブ構成は変更していない。
- 残る確認: OSのグローバルキー入力経路で送信できる方法を使い、画面切替→タブ切替→文字入力を検証する。

### 2026-09-10 ロック解除後の実機確認

- CGEventのHID経路によるキー送信を実施。Control + Option + 1 で Work タブが選択され、前面アプリがテキストエディットへ移ったことをAXとログで確認。既存書類には入力していない。
- 接続画面は内蔵ディスプレイ1台のみ。Control + Option + → はフォーカス・マウス位置を変えなかった。
- 確認後は Control + Option + 2 で元の Chat タブへ戻した。
- 画面間切替から文字入力までの検証は、外部ディスプレイ再接続後に実施する。

### 2026-09-12 外部ディスプレイ接続後の実機確認

- 内蔵1920×1200、LG ULTRAWIDE 3440×1440、LG HDR WQHD 3440×1440、VA27UCPS 1080×1920の4画面。外部画面は左側と上下に配置。
- CGEventのHID経路で検証。矢印イベントは `.maskSecondaryFn` / `.maskNumericPad` を補い、押下時間を設けた。補正前の送信では画面切替が発火しなかったが、補正後は発火。アプリの変更は行っていない。
- 前面アプリとAXフォーカス窓の座標により、内蔵→左端→上段→下段→内蔵の4画面巡回を確認。逆方向移動も確認。
- 下段の外部画面からControl + Option + →、Control + Option + 1を約50ms間隔で送信。内蔵画面のWorkタブへ切り替わり、直前に選んだ確認用テキスト書類がフォーカスを取得。
- 続いてCGEventで文字キーを送信し、確認用書類の先頭に「あ」が入力されたことをAXと保存ファイルで確認。マウスポインタは検証中ずっと外部画面上の同一座標に留まった。
- Control + TabでChat、Control + Shift + TabでWorkへ戻り、確認用書類にフォーカスが戻ることを確認。
- 確認用書類は `/tmp/TabDesk-display-qa-0912.txt` に保存して閉じた。自動的に登録が解除されたことを確認。
- 元のChatタブと上段画面のフォーカスへ戻した。実行前後の保存状態を比較し、全画面の選択タブ・登録窓ID・既存窓の保存座標が一致。既存書類の内容は編集していない。
