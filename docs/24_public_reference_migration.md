## 消滅と不明の区別

`invalidUIElement` は参照の無効を示し、窓自体を閉じた証明ではない。
参照が無効で、別に取得できた健全なAX窓一覧にも含まれない場合は、参照の失効として扱う。
参照の失効だけなら登録を残す。アプリの破棄通知を受けた場合だけ、既存の猶予付き削除経路を使う。
タイムアウト・権限エラー・空一覧だけでは失効と判断しない。アプリごと終了した場合も保存登録は残す。

根拠: [Apple AXError.invalidUIElement](https://developer.apple.com/documentation/applicationservices/axerror/invaliduielement)。
公開AX参照からOSの窓番号への厳密な一対一変換は提供されないため、撮影の照合は補助的な推定であり、操作対象の再同定や登録削除には使わない。

実機検証は専用Fixtureだけを操作する。利用中のTabDeskを入れ替えず、保存設定にも書き込まない。
最初の試行はロック状態の記録と重なったため合格扱いにしない。
ロック解除後の試行でも、画面をまたぐ退避から直後に復元した際、書き込みが成功を返す一方で元の位置へ戻らない現象を確認した。
基準コミット `551a0d3` のCoreでも同じ現象を再現した。移行前から存在していた復元の問題。
画面間移動中は位置書き込みが成功を返しても窓が退避位置に残ることがある。
終了時に既にあった位置再適用処理を、通常の切り替えで画面外に残った場合にも適用した。
100ms待って世代・所属・操作可否を再確認し、位置だけを1回再適用、250ms後に読み戻す。
復元できなければ失敗として保存座標・退避フラグを維持する。通常の成功経路には待機を追加しない。
切り替え所要時間のログにも、この確認時間を含める。
不要なサイズ変更を省く案だけでは再現が止まらなかったため、その案は採用せず従来のサイズ→位置→サイズの順を維持した。

修正後は `reference-final-run/engine-check.log` で、同名窓の識別・登録・タブ切り替え・終了復旧・消滅通知なしの参照失効と登録保持がすべて成功。
`layout-normal.log`、`layout-fullscreen.log`、`layout-restored.log` で通常表示の実移動、全画面中の4操作拒否、全画面解除後の実移動を確認した。
ユーザーの `state.json` / `hotkeys.json` のSHA-256は試験前後で一致した。
保存設定のコピー（6タブ・8登録）を新実装で読み書きし、さらに基準コミットで読み書きして、JSONの全値が一致した。
